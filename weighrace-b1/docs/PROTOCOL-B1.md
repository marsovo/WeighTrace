# AFU-BH-TZ-B1（蚂蚁阿福 B1 · 薄荷联名款）协议笔记

2026-10-26 由真机抓包逆向（iPhone 蓝牙扫描 App 连接实测）。B1 与 A1（AFU-WL-TZ-A1，
沃莱平台）是**两个不同的硬件/协议平台**，仅共用"蚂蚁阿福"品牌外壳。

## 设备身份

| 项目 | B1 | A1（对照） |
|---|---|---|
| 广播名 | `AFU-BH-TZ-B1` | `AFU-WL-TZ-A1` |
| 芯片 | Nordic nRF5（nRF5DFU） | — |
| 广播 Service Data | UUID `FC50`，`AF01 0201 45C4 19D1 E05C A7` | UUID `27AC`（0xAC 协议） |
| 数据服务 | `FC50` | `FFB0` |

## GATT 结构

标准服务：1800 / 1801 / 180A（型号、序列号、固件字符串）、180F 电量、
Nordic Legacy DFU（00001530-…，官方 SDK 固件）。

自定义服务 **FC50**（128 位 UUID 基址 `AF00000X-9F2D-4C8A-8D6F-6A7B45F90000`）：

| 特征 | 属性 | 用途 |
|---|---|---|
| AF000002 | Write | App → 秤命令 |
| AF000003 | Notify | **测量数据主通道**（值可直接读取） |
| AF000004 | Indicate | 尚未观察到数据 |
| AF000005 | Write Without Response | 命令 |
| AF000006 | Write | 命令 |

实测：连接后**无需任何握手写入**，读取/订阅 AF000003 即可获得数据帧。

## AF000003 帧格式（20 字节）

| 字节 | 含义 | 证据 |
|---|---|---|
| [0] | 帧头 `0xAF` | 全部样本 |
| [1] | 固定 `0x45` | 全部样本 |
| [2..3] | **体重：u16 小端序，单位克** | ✅ 两组验证：`34 9E`→40500 g（秤面 40.5 kg）；`20 FD`→64800 g（秤面 64.80 kg），均精确到克 |
| [4] | `0x48` 固定 | 全部样本 |
| [5] | bit7 = **体重有效标志**：有锁定体重时 0x80，归零帧 0x00 | 样本 8 对照确认（4880 ↔ 4800） |
| [6..7] | u16 大端 = 543，**常量** | 穿袜实验已证伪阻抗猜想：绝缘条件下真阻抗不可能保持一字不变（样本 4） |
| [8..10] | 0 | — |
| [11] | 94 → 93（两次测量间） | 疑似电量 %（负载浮动），待定 |
| [12..17] | 全 0 | 预留（历史/多用户槽位？） |
| [18] | 子类型：`0x51` = 测量帧，`0x52` = 状态帧 | 状态帧样本除 [2..5]=`01 00 AD 01` 外全 0，不含体重 |
| [19] | **校验和**：(字节 [2..18] 之和) & 0x1F | ✅ v1.13 定案：本表全部样本帧逐一验过（见 v1.13 节） |

## 状态帧格式（子类型 0x52）

| 字节 | 含义 | 证据 |
|---|---|---|
| [0..1] | `AF 45` | 同测量帧 |
| [2..3] | `01 00` 固定 | 全部状态帧样本 |
| [4..5] | **阻抗：u16 小端序，单位 Ω**（无有效接触时为 0） | ✅ 光脚站立 = FA01 → 506 Ω；穿袜 = 0000（绝缘测不到）；重连无人 = 0000；部分载荷接触 = AD01 → 429 |
| [6..17] | 全 0 | 全部样本 |
| [18] | `0x52` | 子类型 |
| [19] | 校验和（同测量帧） | ✅ v1.13 定案（内容相同校验相同与该公式一致） |

样本：

```
测量帧（站立 40.5 kg）  AF45 349E 4880 021F 0000 005E 0000 0000 0000 510A
测量帧（站立 64.80 kg） AF45 20FD 4880 021F 0000 005D 0000 0000 0000 5114
测量帧（下秤归零）      AF45 0000 4800 021F 0000 005D 0000 0000 0000 5117
状态帧（光脚站立）      AF45 0100 FA01 0000 0000 0000 0000 0000 0000 520E
状态帧（穿袜/无人）     AF45 0100 0000 0000 0000 0000 0000 0000 0000 5213
```

## App 侧实现（本仓库 B1 补丁）

- `ScaleManager.didDiscover`：名称前缀接受 `AFU-BH`（B1 无 27AC 身份数据，按名称识别）。
- `ScaleManager.didConnect`：服务发现同时包含 FFB0 与 FC50；特征订阅逻辑原本即为
  "订阅全部 notify/indicate"，无需改动。
- `AFUPacket`：`0xAF` 开头帧按 [18] 子类型分发——0x51 → weight；0x52 且 [4..5]
  非零 → impedance（`adcs` 返回 [4..5] 小端 Ω 值，复用既有 ADC 选择/归一化流程）；
  0x52 全零 → settings 忽略。`weight` 按 [2..3] 小端克解码；`stable` = 0x51 帧、
  体重 > 0 且 byte[5] 的 0x80 标志位置位；新增 `isBHMeasurement` 标记。
- `receive(_:)` 的 weight 分支：B1 的阻抗在状态帧里、与体重帧异步到达（任意先后
  均可，第二个到达者触发既有保存流程）。**v1.2（首测复盘后）**：真机首测（光脚）
  阻抗未赶上 v1.1 的 4 秒回退保存（存成 0 Ω 兜底体脂）——改为：稳定帧后主动轮询
  AF000003（+2/5/9/14 秒各读一次，防状态帧只换值不推送）、回退窗口放宽到 20 秒、
  下秤零帧立即用待存体重结算、BH 帧不再触发原有的"新测量清零阻抗"（防交错帧互踩）。
  **真机验证通过（2026-10-26 23:37）**：v1.2 光脚站立，App 保存 63.80 kg、
  阻抗 **503 Ω**、Segal 体脂 **13.1%**（与手算逐项一致）——发现/连接/体重/真阻抗/
  体成分/本地保存全链路打通，B1 支持完成。后续可选：同工程改跑 iPhone（写苹果健康）。
  **v1.3（2026-10-27，用户要求删 ADC 2）**：移除 ProfileView 的"阻抗选择"选择器、
  HistoryView 的"ADC 对比"工具栏入口、ImpedanceADCChoice 的 .second 分支。其余
  带 ADC 2 字样的显示（主页/详情/复核页）均以"阻抗数 ≥ 2"为渲染条件，B1 记录
  永不触发；底层双通道换算代码保留不动（A1 逻辑，抽除风险大于收益）。
  **v1.4（2026-10-27）**：用户指出首页仍有"ADC 1"字样——Dashboard 的实时徽标与
  记录小字（"本次采用 ADC 1，双路数据按实际接收保存"）、History 列表徽标均无条件
  渲染 ADC 编号，已全部改为只显示阻抗数值（如"494 Ω"）。

## 补丁 v1.6（2026-10-27）：修复旧结果重复弹出

现象：一次测量保存后，下一次上秤时又弹出一遍上一次的结果。
根因：稳定帧武装的 20 秒"无阻抗兜底"任务按 pendingBHWeight 认领；保存成功或
离秤后该值未清零，人再次上秤（hasSavedMeasurement 已被离秤重置）时，残留的
兜底任务把上一次的体重又 finishMeasurement() 了一遍，重复存档并弹出结果页。
修复：finishMeasurement() 保存成功即 pendingBHWeight = 0；离秤（<1 kg）时
同样清零。兜底任务原有判据（pendingBHWeight == 武装时体重且 > 0）随之对残留
任务永假。另：主动轮询读特征前增加 .read 属性检查，消除日志里的
"Reading is not permitted" 噪声。

## 补丁 v1.13（2026-11-08）：Holtek 算法 + 秤内历史导入

写侧协议与 0x54 布局来自开源项目 OHealthBridge（github.com/1083508656/
OHealthBridge-mi-scale1，其 B1 支持标注"已实测"）对官方健康 App 流程的
逆向；本项目此前只被动读帧，从未向秤写入。以下写侧行为**尚未经本项目
真机抓包复核**，首次联调以 App 调试日志为准（`B1 TX queued` /
`Stored record imported` / `checksum mismatch` 三类行）。

### 校验和（定案）

[19] = (字节 [2..18] 之和) & 0x1F。验证：本文档 5 个样本帧（3 测量 +
2 状态）代入全部吻合（0A / 14 / 17 / 0E / 13）。与 OHealthBridge 的
isValid 实现一致。v1.13 用法：0x54 / 0x5F 新路径强制校验，不过校验的
帧丢弃；0x51 / 0x52 存量路径只记日志不拦截（防真机未知帧型误杀）。

### 写侧（AF000002，全部 20 字节帧，布局同读侧）

连接且 FC50 特征就绪后，每连接一次，串行队列依次写：

1. 时钟同步：子类型 0x5F，[2]=0x16，[3..6]=当前 Unix 秒（小端），[7]=0x20。
2. 两帧固定同步帧（子类型 0x62，内容逐字取自参考实现，含其 [2]=0x04 起
   的 16 字节载荷），随后是档案帧。
3. 档案帧（子类型 0x61）：[2]=变体码，[3..6]=Unix 秒，[8]=用户槽位，
   [9]=0xAF，[10]=变体开锁字节，[11]=0x17，[12]=年龄，[13]=性别（男 1），
   [14..15]=目标体重 ×100（小端），[16]=0x03。变体：INITIAL 3F/B6、
   GET_WEIGH_AGAIN_1 4B/B6、GET_WEIGH_AGAIN_2 5B/D9、FINAL 68/D9、
   HISTORY_DUMP 8E/DE。本 App 发 INITIAL + HISTORY_DUMP（以本人资料、
   槽位 0）；12 秒内无 0x54 到达则重发一次 HISTORY_DUMP。
4. 测量收尾：阻抗帧（[2]=0x01 有效标志置位时）回 ACK（0x5F，[2]=0x12，
   [3]=0x52），每秤次再补一帧 FINAL 档案帧关闭秤侧测量周期。
5. 报告块（0x5F 且 [2]=0x14）回 ACK（[3]=0x14）。

构造器在 AFUPacket.swift 的 AFUCommand 中，与参考 Kotlin 实现逐字节
比对过（10 组用例含各变体档案帧与 ACK，离线校验脚本全过）。

### 存储帧（子类型 0x54）

| 字节 | 含义 |
|---|---|
| [2] | meta：低 2 位 = 记录类型，高 6 位 = 序号（ACK 时回填 [5]） |
| [3..6] | 称重时间 Unix 秒（小端） |
| [7..10] | flags（小端 u32）：低 18 位 = 体重克数，bit31 = 锁定标志 |
| [13..14] | 阻抗 Ω（小端），无则 0 |

导入规则（ScaleManager.importStoredRecord）：校验和先行；与本地历史按
（时间差 < 120 秒 且 体重差 < 0.05 kg）去重（秤重放内存会重复到达，
且两端时钟可能漂移）；成员按体重自动归属；用记录自带时间与阻抗按当前
算法设置计算体成分；只入本地历史，不写 Apple 健康、不弹结果页。
连接时若用户正站在秤上，同一秤次可能既被回放又被实时保存——
finishMeasurement 保存前先查同成员近 120 秒同体重记录，有则直接采用。

### Holtek 算法（algorithmVersion = holtek_v1）

小米/Zepp Life（Holtek）单频公式组，自 OHealthBridge 的 BodyFatMeasureHook
移植（其注释称逆向自官方 JNI）：

- LBM = (h×9.058/100)×(h/100) + w×0.32 + 12.226 − R×0.0068 − 年龄×0.0542
  （h 为身高 cm，w 为体重 kg，R 为阻抗 Ω）。
- 体脂 = (1 − (LBM − 修正)×系数/w)×100：修正 女≤49 岁 9.25、男>49 岁
  7.25、余 0.8；系数 男<61 kg 0.98、女>60 kg 0.96、女<50 kg 1.02
  （后两档身高>160 再 ×1.03）；结果 >63 记 75。
- 骨量 = −(基值 − LBM×0.05158)（基值 男 0.18016894 / 女 0.245691014），
  >2.2 再 +0.1 否则 −0.1，女>5.1 / 男>5.2 记 8。
- 肌肉 = w − 体脂量 − 骨量；水分 = (100−体脂)×0.7 再按 <50 取 ×1.02 /
  否则 ×0.98；内脏脂肪按性别两套分支公式；BMR 用 Mifflin-St Jeor；
  皮下脂肪 = 体脂×0.85；蛋白质为源实现的固定 16%。

与本项目数据的对照（身高 173、男）：官方同场 65.5 kg / 体脂 18.0% 时，
Segal 约 13.7–14.0%（年龄 26–28 口径，下同），Holtek 约 16.5–16.7%——
差距由约 −4.2 点收窄到约 −1.4 点；真机验证记录 63.80 kg / 503 Ω：
Segal 13.1%，Holtek 15.2%。注意官方阻抗口径本身存疑（CAPTURES 定案：
官方等效阻抗约 630 Ω vs 实测约 500 Ω），Holtek 更贴近的是官方的**显示
口径**，不等于更接近真实体成分。默认算法仍为 Segal（2026-10-26 用户
拍板"就用 Segal 原公式"未变），Holtek 在「我的」页切换。

移植偏差（有意为之，均已在代码注释标明）：结果钳制到本 App 的合理
存储区间（体脂 [3/8, 75]、水分 [25, 80]、骨量 [0.5, 8] kg、肌肉
[0, 体重]、内脏 [0, 30]）；源公式女性轻体重分支算出的内脏指数 ≤0 时
不存该项（详情页不显示）；骨骼肌沿用本 App 既有的肌肉 ×0.527 派生
（源为 ×0.55）；内脏/基础代谢/皮下脂肪不写入 Apple 健康。
